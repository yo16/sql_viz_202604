# SQL Lineage Visualizer — 要件定義

## 概要

DWH構築時に使用される膨大なSQLクエリ群の**カラムレベルリネージュ**を可視化するWebツール。
中間テーブル作成の連鎖（A→B→C）において、最終テーブルのカラムが元々どのテーブル・カラムに由来するか、どのような条件でフィルターされているかを追跡可能にする。

**想定ユーザー**: DWHを構築・運用する開発者

## フェーズ構成

| フェーズ | スコープ | 概要 |
|---|---|---|
| 1 | 単一クエリ可視化 | 1つのSQLクエリの構造をbox-in-box形式で可視化 |
| 2 | 複数クエリ連携 | 複数クエリ間のテーブル依存関係を左→右のフローで可視化 |
| 3 | 認証・永続化 | ユーザー認証、クエリ・可視化結果の保存 |
| 4 | 課金 | Stripeによるサブスクリプション課金 |

**本ドキュメントはフェーズ1・2を主な対象とする。フェーズ3・4は方針のみ記載。**

## フェーズ1: 単一クエリ可視化

### 機能要件

#### F1-1: SQL入力

- テキストエリアへの直接入力
- SQLファイル(.sql)のドラッグ&ドロップ
- 複数ファイルの登録が可能
- 1ファイルに単一SQLでも複数SQLでも対応
- 対象DB方言の選択（初期実装: Google BigQuery）
  - 将来的にPostgreSQL、MySQL等を追加可能な設計とする

#### F1-2: SQLパース

- サーバーサイド（Next.js API Routes）で実行
- パーサー: [node-sql-parser](https://github.com/taozhi8833998/node-sql-parser)
- 対応する句:
  - SELECT句
  - FROM句（JOIN含む）
  - WHERE句
  - GROUP BY句
  - HAVING句
  - ORDER BY句
- WITH句（CTE）、サブクエリも可視化対象
- パースエラー時はユーザーにわかりやすくエラー内容を表示

#### F1-3: 単一クエリの可視化

- React Flowを使用したノードベースの可視化
- **Box-in-Box構造**:
  - 最外枠: クエリ全体（= 1テーブル）
  - 中枠: 各句（SELECT, FROM, WHERE, ...）
  - 内枠: 各カラム・条件
- JOIN表現:
  - FROM句内にJOINがある場合、JOINの種類（INNER/LEFT/RIGHT/FULL等）をアイコンで区別
  - 視覚的には控えめな違い（「よく見れば違う」程度の強度）
  - 結合条件も表示

#### F1-4: インタラクション

- ズーム / パン
- テーブル（クエリ）boxのドラッグによる位置並べ替え
- テーブル box の**右下ドラッグによるリサイズ** (bd-sql_viz_202604_2-eqv):
  - 対象: QueryBoxNode, UnresolvedBoxNode のみ（ClauseBox / ColumnItem は対象外）
  - React Flow の `NodeResizeControl` を使用、minWidth=180 / minHeight=60
  - ドラッグ可能なのは**ルートのQueryBox/UnresolvedBoxのみ**。内部のClauseBox（SELECT/FROM/WHERE）および ColumnItem は固定でドラッグ不可（bd-sql_viz_202604_2-35o）
- boxクリックでの表示モード切替（トグル）:
  - **詳細表示**: クエリの全句構造を展開表示
    - 句は**2 列レイアウト**で表示する（bd-sql_viz_202604_2-8ud）:
      - **左列**: SELECT 以外の句 (`FROM → WHERE → GROUP BY → HAVING → ORDER BY`) を実行順で縦積み
      - **右列**: SELECT 句（列リストを持つため列数に応じて高さが伸びる）
      - 以前 (bd-q82) は 6 句を全て横一列に配置していたが、展開時の幅が大きすぎるため 2 列に変更
    - SELECT句: ClauseBoxNode 内に各カラムを ColumnItemNode として表示
    - FROM句: ClauseBoxNode のラベルに参照テーブル名と JOIN 情報を表示（bd-sql_viz_202604_2-c69）
    - WHERE/GROUP BY/HAVING/ORDER BY: ClauseBoxNode のラベルに条件式・式テキストを表示
    - 該当する句が無い場合はその clauseBox を生成しない（左詰めで詰める）
    - SELECT 以外の ClauseBox は固定幅で表示しているため長い label が `...` で省略される。**ヘッダの ▸/▾ クリックで縦展開可能**にし、複数行で読めるようにする（bd-sql_viz_202604_2-oi5）
    - CTEやサブクエリを持つクエリでも、ネスト子ノードの下にメインクエリの clauseBox 群を横並び配置する（bd-sql_viz_202604_2-u8l, bd-sql_viz_202604_2-q82）
  - **カラム一覧表示**: SELECT句のカラム名のみをコンパクトに表示
- **全部開く / 全部閉じるボタン** (bd-sql_viz_202604_2-f4z):
  - FlowCanvas 右上に「全部開く」「全部閉じる」ボタンを配置
  - 「全部開く」: 全 QueryBox / UnresolvedBox を detail に一括切替（`expandAll()`）
  - 「全部閉じる」: 全ノードを compact に一括切替（`compactAll()`）
  - 各タイトルバーを1つずつクリックするのと同じ動作を全ノードに対して一括実行

#### F1-5: CREATE TABLE AS SELECT 対応

- `CREATE TABLE {テーブル名} AS SELECT ...` 形式のクエリに対応
- boxの中身（句構造・カラム）は単純SELECTと同一形式で表示
- boxのタイトルはCREATE先テーブル名を使用

#### F1-6: 単純SELECTクエリの表示

- targetTableがない単純SELECTクエリのboxタイトルは「[問い合わせ]」とする

#### F1-7: リセット機能

- すべての入力・パース結果・可視化をクリアして初期状態に戻すリセットボタン
- クリア対象（bd-sql_viz_202604_2-5zc）:
  - lineageStore のテーブル/クエリ
  - flowStore のノード/エッジ（lineageStore 経由で連動）
  - SqlInputPanel の入力テキスト
  - FileDropZone の読み込み済みファイルリスト
- 実装: lineageStore に `resetCounter: number` を持ち `resetAll` で +1。SqlInputPanel と FileDropZone がこのカウンタを購読し、変化を検知して local state をクリアする

#### F1-8: CTE・サブクエリの入れ子表示

- CTE（WITH句）およびサブクエリ（FROM句・WHERE句）を、親クエリのbox内に入れ子構造で描画する
- CTE: 親box内にCTE名をタイトルとしたboxを配置、通常のSELECTと同じ句構造で表示
- FROM句サブクエリ: エイリアス名をタイトルとしたbox
- WHERE IN/EXISTS サブクエリ: 「[サブクエリ]」をタイトルとしたbox（エイリアスがあればそれ）
- CTE / FROMサブクエリ / WHEREサブクエリなどの**ネスト子**は、依存順で**左→右**に並べる（bd-sql_viz_202604_2-47d）
  - 例: `WITH a AS (...), b AS (SELECT FROM a)` → `a` が左、`b` が右
  - 「先に行われる処理は左、次は右」を入れ子の中でも統一する
- CTE間の依存関係も内部エッジとして描画（左→右のフロー）
- 外部テーブルからCTE内テーブルへのエッジは親box境界を貫通
- compact時: 入れ子を隠し、親boxのカラムリストのみ表示
- detail時: 入れ子構造を全展開
- 親boxのサイズは子ノードの内容に応じて動的に拡大する（子ノードが展開されたとき、親boxも包含するサイズに広がる）
- ネスト上限: 5段まで分析・表示、6段以上は「...（省略）」表示

## フェーズ2: 複数クエリ連携

### 機能要件

#### F2-1: テーブル依存関係の自動検出

- BのFROM句にテーブルAが出現すれば「A→B」の依存関係として自動認識
- 順序推定: FROM句に参照されるテーブルが先（左側）に配置される
- レイアウト: 左→右方向のフロー
  - あるboxの右端から出るエッジが別boxの左端に接続する場合、前者を左、後者を右に配置する（トポロジカル順）
  - 実装: `arrangeTableNodes()` を `syncFromLineage` から呼び出し、`table_dependency` エッジに基づきレイヤーごとに x 座標を割り当てる（bd-sql_viz_202604_2-z0e）
- **エッジの接続先 Handle** (bd-sql_viz_202604_2-q8n):
  - target が **detail モード**: target QueryBox の **FROM clauseBox** の左端に接続
  - target が **compact モード**: target QueryBox 全体の左端中央に接続
  - source 側は常に source QueryBox の右端中央
  - 対象は `table_dependency` エッジのみ。`column_lineage` エッジは columnItem に直接接続される現状動作を維持

#### F2-2: 未認識テーブルの扱い

- あるクエリのFROM句に参照されるテーブルがまだ登録されていない場合:
  - 「未登録テーブル」として架空のbox（外観で区別可能）を描画
  - 後からそのテーブルを生成するSQLが登録されたら、架空boxを正式なboxに置換

#### F2-3: カラムレベルリネージュ

- カラム名クリック時に、そのカラムの出自をリネージュとして**上流＋下流の両方向**に辿る（bd-sql_viz_202604_2-26k）
- 辿れるパス（A.col_x → B.col_y → C.col_z）をハイライト表示
- ハイライト対象:
  - **エッジ（線）**: リネージュチェーン上の `column_lineage` エッジが赤系カラー（`--color-edge-highlighted`）で強調表示。**アニメーション付き破線**で方向性を示す — **トリガー列から外向き**に流れる: 上流エッジは target→source 方向、下流エッジは source→target 方向にアニメーション（bd-sql_viz_202604_2-d58 / bd-sql_viz_202604_2-2vk）
  - **カラム項目（ColumnItemNode / UnresolvedBoxNode）**: チェーン上の全カラム（上流＋下流）が薄い赤で強調表示。**クリックしたトリガー列**はより濃い赤＋太枠＋太字で目立たせる（bd-sql_viz_202604_2-d58 / bd-sql_viz_202604_2-2vk）
  - 対象外のカラム/エッジは dim（薄く）表示
- 再クリックで解除、キャンバス空白クリックでも解除

#### F2-4: 未登録テーブルのカラム推定表示

- 未登録テーブル（FROM参照のみ）のカラムをクエリ内の参照情報から推定して表示
- 収集対象: SELECT句・JOIN ON条件・集約関数内部・CASE式・関数引数のカラム参照
- エイリアス→実テーブル名の逆引きで正しいテーブルに紐付け
- FROMが1テーブルの場合、テーブルプレフィックスなしのカラムはそのテーブルに帰属
- 複数テーブルでプレフィックスなしの場合は収集しない（不明扱い）
- エッジケース詳細: `doc/design/column-inference-edge-cases.md`

#### F2-5: SELECT * のカラム解決

- A→Bのリネージュで、BがSELECT * FROM Aの場合:
  - Aのカラムが確定済みなら、Aの全カラムをBの出力に引き継ぐ
- SELECT t.* にも対応（特定テーブルのカラムのみ伝播）
- 依存グラフのトポロジカル順（左→右）で再帰的に伝播

#### F2-6: 手動関連付け（優先度: 低）

- パーサーの限界等で出自不明なカラム・テーブルが発生した場合:
  - 「出自不明」であることを明確に表示
  - ユーザーが手動で関連付けを設定できるUI

## 横断機能: 多言語対応（日本語 / 英語切替）

フェーズに依存しないUI横断機能として、日本語と英語の表示切替を提供する。

### FI-1: 言語切替UI

- ヘッダー右側に言語トグル（JA / EN）を配置
- クリックで即座に画面全体のテキストが切り替わる（リロード不要）
- 切替時に `<html lang>` 属性も `"ja"` / `"en"` に更新する（スクリーンリーダー・アクセシビリティ対応）

### FI-2: 初期言語の自動判定

- `navigator.language` が取得できる場合:
  - 値が `"ja"` で始まる → 日本語
  - それ以外（`en-US`, `zh-CN` 等を含む） → 英語
- `navigator.language` が取得できない場合 → 日本語
- ただし FI-3 の保存値がある場合はそちらを優先する

### FI-3: 選択状態の永続化

- ユーザーがトグルで選択した言語は `localStorage` に保存する
- 次回訪問時は保存値を優先して初期言語を決定する（無ければ FI-2 の自動判定）
- 保存キーの具体名は設計ドキュメント (`doc/design/i18n.md`) で定義

### FI-4: 翻訳リソースの構成

- 日本語・英語の 2 つの静的リソースファイルをアプリケーションに同梱する
- 外部API等による動的翻訳は行わない
- 未翻訳キーが発生した場合のフォールバックは英語とする

### FI-5: 翻訳対象と翻訳対象外の区別

**翻訳対象**:
- UIラベル（ボタン、メニュー、パネル見出し等）
- アプリケーションが表示する自前のエラーメッセージ・バリデーションメッセージ
- フッターの説明文言（「Small Piece」「Contact」以外の地の文）
- クエリ / サブクエリ / 未登録テーブルの表示ラベル（例: 「[問い合わせ]」「[サブクエリ]」「未登録テーブル」）

**翻訳対象外（日本語・英語両方で同一表示）**:
- ヘッダータイトル「SQL Lineage Viz」
- フッターの提供元名「Small Piece」および「Contact」
- SQLキーワード（SELECT / FROM / JOIN / WHERE 等）
- DB方言名（Google BigQuery / PostgreSQL 等）
- ユーザー入力SQLの内容、テーブル名、カラム名（システムが翻訳すべき対象ではない）
- `node-sql-parser` が返すパースエラーメッセージの原文（日本語選択時も英語原文のまま表示する）

**表記ルールの補足**:
- 句のラベルは、日本語版では「SELECT句」「FROM句」のように "句" を付与し、英語版では "clause" を省略して `SELECT` / `FROM` のように句名のみ表記する

### FI-6: metadata（SEO）の扱い

- Next.js の `metadata` export（`<title>`, `description`, `openGraph`, `twitter`, `keywords`, JSON-LD 等）は**英語固定**とする
- クライアント側の言語切替では metadata を変更しない（URL不変方針のため SEO向けの言語別出力は行わない）
- SSR 初期出力の `<html lang>` も英語とし、metadata と整合させる
- 画面内の表示テキストおよび `<html lang>` 属性はクライアント側の言語切替に追従する

### FI-7: 翻訳リソースの一貫性保証

- 日本語リソースと英語リソースは同一のキー集合を持つこと
- キーの網羅性と同期は設計ドキュメントで管理する（具体運用は `doc/design/i18n.md`）

## 非機能要件

### 技術スタック

| 区分 | 技術 |
|---|---|
| フレームワーク | Next.js (App Router) |
| 可視化ライブラリ | React Flow |
| SQLパーサー | node-sql-parser（サーバーサイド） |
| スタイリング | CSS Modules（Tailwind CSS 禁止） |
| デプロイ | Vercel |
| テスト | Jest（+ Playwright: E2E必要時） |
| DB/Auth | Supabase（フェーズ3で導入） |

### 対象DB方言

| 優先度 | DB |
|---|---|
| 初期実装 | Google BigQuery |
| 将来対応 | PostgreSQL, MySQL, SQLite 等 |

node-sql-parserが対応するDB方言を選択UIで切り替え可能にする。

### パフォーマンス

- 数十クエリ規模のリネージュを快適に操作できること
- React Flowのノード数が多い場合でもズーム・パンがスムーズであること

### UI/UX方針

- 開発者向けのシンプルで機能的なデザイン
- 可視化エリアを最大限に確保
- 左→右方向の自然なフロー表現
